# AGENTS.md — opencode-mobile (Iran-friendly fork)

## What this repo is

An Android (and, secondarily, web) client for the [opencode](https://github.com/sst/opencode)
AI coding agent. Fork of [`dzianisv/opencode-mobile`](https://github.com/dzianisv/opencode-mobile) (MIT),
stripped of every dependency that is unavailable or blocked in Iran: **no Google Play
Services, no Firebase/FCM, no PostHog, no Sentry, no expo-store-review, no third-party push**.

Hard constraint: **do not add** Google Play Services, Firebase, FCM, PostHog, Sentry, or any
third-party analytics/push SDK. Background push is done with the local `bridge/` relay to
**ntfy** (self-hostable). Keep it that way.

## Layout

```
app/                       Expo Router screens ((tabs), session/[id], connection/*)
src/components/            UI (chat/, markdown/, AuthGate, ...)
src/lib/                   sdk.ts (HTTP+SSE client), notifications.ts, storage.ts,
                           usage-limit.ts, i18n/, ...
src/stores/                zustand: sessions, connections, events, settings, auth
bridge/                    notify-bridge.mjs — opencode SSE -> ntfy (dependency-free)
scripts/                   check-version-parity.mjs + the CUA smoke script
.github/workflows/         build.yml (APK + web), security-scan.yml (gitleaks)
```

`android/` and `ios/` are **generated by `expo prebuild`** and are gitignored — do not commit them.

## Key patterns

- **SSE is the source of truth.** `events.ts` connects to `GET /global/event` and dispatches to
  the other stores. `sendMessage` is fire-and-forget; UI updates arrive via SSE.
- **Storage** goes through `src/lib/storage.ts` (keystore on native, localStorage on web).
  New persisted keys must be added to `ALLOWED_PERSISTED_KEYS` in
  `src/lib/persisted-keys.test.ts` with a note. Never persist model/tool output.
- **Notifications** are categorized in `src/lib/notifications.ts`; `usage-limit.ts` classifies
  rate/quota errors so they route to the `limits` category (in-app) and the bridge.
- **No Sentry/PostHog:** `sentry.ts` and `analytics.ts` are local no-op shims kept for
  call-site compatibility.

## Conventions

- Prefer `const`; early returns over `else`; avoid `try/catch` where possible; avoid `any`.
- Tests are `node:test` files (`*.test.ts` in `src/`, `*.test.mjs` in `scripts/` and `bridge/`).
- Keep comments explaining *why*, not *what*.

## Running & testing

```bash
npm install
npm test          # Node 22.17+, uses --experimental-strip-types
npm run typecheck
npm run check:versions
npm run export:web        # static SPA build -> dist/ (served from a trusted origin)
npm run bridge            # relay opencode events to ntfy (see bridge/README.md)
```

Local Android build: `npx expo prebuild --platform android && npx expo run:android`.
**Do not install the Android SDK on a system disk** if you can avoid it; point
`ANDROID_HOME`/`GRADLE_USER_HOME` at an external disk. From Iran, add a Maven mirror for
`google()`/`mavenCentral()`.

## CI

`build.yml` runs on push/PR to `main` and on `v*` tags:
- `test` — version check, typecheck, unit tests
- `build` — `expo prebuild --clean` + `./gradlew assembleRelease`, uploads `app-release` (APK)
- `web` — `expo export --platform web`, uploads `web-dist`
- `release` — on a `v*` tag, attaches the APK to a GitHub Release

The APK is the primary deliverable and is sideloaded (see README). If a Gradle build fails,
the error is published as a check-run annotation (readable without authenticated log access).
