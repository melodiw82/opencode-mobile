# Ship an Android APK

The APK is built by `.github/workflows/build.yml` on GitHub's runners; nothing is built
locally (no Android SDK required, and Maven/Google mirrors may be blocked in Iran).

## Steps

1. Bump the version in **both** `package.json` and `app.json` (`expo.version` and
   `expo.android.versionCode`). They must match or CI fails.
2. Verify locally:
   ```bash
   npm test
   npm run typecheck
   npm run check:versions
   ```
3. Commit, push to `main` — this produces an `app-release` artifact (the APK).
4. For a tagged release (GitHub Release with the APK attached):
   ```bash
   git tag v0.4.16 && git push origin v0.4.16
   ```

## Notes

- `android/` is generated by `expo prebuild --clean` in CI and is intentionally not
  committed. Never commit it.
- Release signing uses the `KEYSTORE_BASE64` / `KEYSTORE_PASSWORD` / `KEY_ALIAS` /
  `KEY_PASSWORD` repo secrets; without them the APK is debug-signed (fine for sideloading).
- If the Gradle step fails, read the check-run annotation — the error is published there
  because workflow logs need authentication.
